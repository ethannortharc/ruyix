# 智能体的工作：派出去、看得见、收得回（设计）

2026-10-18 · Ethan：Ruyix 是 agent OS，桌面要围着**智能体的工作**转，不再是围着人点页面转。三个目的：

1. **派活**清楚、直接、简单：一句话把事情分出去。
2. **在做的状态和做完的结果**清楚，而且好看、有科技感。
3. 人要关心的部分——**会话、结果、过程里要人拍板的地方**——都有一个合适的地方和样子。

他说的具体想法：

- 每个智能体干活时的每一条动态，**像歌词一样**在屏幕上滚动更新；每个智能体至少一条，同一个任务的智能体放在一起。一条流（一个任务）
  一般一行，最多一两行，在桌面上固定的地方滚。
- 做完了，在桌面上留一张**便签**，可以擦掉（不再显示）；所有智能体的工作都记在一个**记录**里，能按智能体、按任务分类查。
- 最终结果用合适的方式**呈现**：PDF、网页、Markdown、视频……在合适的位置打开，渲染好。
- 他平时用命令行（Zellij、tmux）。常驻会话要能在 **tmux / Zellij** 里看、进去；每个常驻会话在桌面上有一个地方，点进去就能看它的状态。
- 会话之间互相发消息时，画成**连线图**：一个光点从这个会话飞到那个会话。
- 工作流里加一个**讨论**节点：到了某一步（智能体觉得要找人确认，或人特意在「调查和结论」之后加一步），桌面上冒出一个聊天的图标，
  点进去和这个智能体讨论；人觉得清楚了，点继续，后面的步骤才走。在这之前任务一直停在那儿等人。
- 界面：整齐、干净，同时现代、高级、好看。清楚的基础上做到简洁。

他定的（2026-10-18）：

- 歌词条在经典桌面**右侧那一栏的最上面**。
- 每一句：**平时按规则写**（不花 token、马上有）；**点开一条时，再用主模型概括**这件事到现在做了什么。
- 常驻会话进 tmux / Zellij：用**镜像**（会话照旧结构化地跑，tmux 里每个会话一个窗口，实时显示对话，打字就是给它发消息）。

## 现在已经有的（main，2026-10-18）

| 想要的 | 现在有什么 | 缺什么 |
|---|---|---|
| 正在做的一览 | `window.__ruyixWork`：运行、池子任务、会话统一成一张单子（状态、步骤段、谁在做、最近一次动作）；各桌面的光点＋步骤环（workspace-15） | 每条只有状态，**没有「它此刻在干什么」的文字流** |
| 智能体干了什么 | 运行的账本（每一步的工具调用、证据）；池子任务的日志；会话的事件（readSession） | 没有统一的「一句话」版本 |
| 做完的 | 「做完没看」的托盘 / 地图上的记录处；看过记在盒子里（markSeen） | 不是便签：看不到结果的一句话和缩略图 |
| 记录 | 工作台的运行列表、指标；智能体页的会话列表 | 分散在两处，不能按智能体、按任务一起查 |
| 结果 | 结果查看器（PDF、网页、视频、音频、图片、Markdown、文本，能写意见、从某步重来），在运行页「结果」里 | 只在运行页里；会话做出的文件看不了 |
| 会话 | 常驻会话（Claude Code / Codex / pi），智能体页「会话」；终端应用（tmux、Zellij） | 两者没接上：会话不在 tmux 里，桌面上没有会话的位置 |
| 智能体之间的消息 | 留言（core/messages）；地图上的流星 | 经典桌面上看不到，也没有「谁和谁」的图 |
| 要人拍板的步骤 | 审阅（带意见、按意见改）、拿主意、填写、去做；结果节点；共用浏览器的交接卡 | 没有「讨论」 |

## 设计

### 1. 派活：一个入口

- 入口还是主智能体（⌘K、语音、对话）。说一句要做的事，主智能体先给一张**派活卡**：打算怎么做（用哪个工作流，或开几个会话、
  各做哪一块、谁来复查）、大概多久、要你在哪里拍板。点「开始」就派出去；想改就直接说。
- 规则不变：能撤销的直接做；花钱、对外、撤销不了的出卡片。会话超过 3 个先问。

### 2. 在做：歌词条（每条流一条）

桌面上固定一个「**正在做**」的地方，每件在做的事一条。

**要的是什么**（Ethan，2026-10-18）：「歌词」只是个比方，要的是**一眼知道它在干活、干到什么状态了**。这类效果通常叫「实时动态」
（Live Activity）或滚动字幕。做好它的要点：

- **活着**：在做的那一行一直在动——当前一句上有一道流光扫过（像「思考中…」那种流光字），一段时间没有新动作也不会看起来像卡住了；
  旁边的用时一秒一秒在走。
- **状态一眼可见**：颜色说状态（在做、等你＝琥珀、出问题＝红、做完＝绿），步骤环说到第几步，用时说多久了。
- **在干什么**：当前一句最亮、最大；前面几句往上浮、变小、变淡，像歌词那样退开——看得出它刚才做了什么，又不抢眼。
- **等你时停住**：琥珀色不滚动，写清等你做什么，点一下就到那里。


```
◐ 公众号：为什么每个人都需要 agent OS          ③/⑤ 写稿 · 6 分钟
  sonnet  读了 draft.md，在改第二段的例子 ▍
  codex   看完封面文案，回了 sonnet：标题用短的那个
```

- **左边**：任务标记（光点＋步骤环，和各桌面一样），标题，第几步、哪一步、多久。
- **右边**：每个智能体一行，**最新的一句在当前行，旧的往上滚走、淡出**——像歌词。正在写的那一行末尾一个光标在闪；工具调用用等宽字，
  说的话用正文字；颜色按智能体（和地图上一样：Claude 橙、Codex 青、dsh 紫）。等你时整条变琥珀色，那一行写「等你：看原稿」。
- 同一个任务的智能体在一条里；会话一个一条；池子任务一个一条。条数多时只滚动显示最要紧的几条（等你 > 在做 > 出问题），其余收成
  「还有 3 件在做」。
- 点一条：展开成这件事的**工作台**（下面第 5 节的会话 / 运行视图），看完整的过程。
- **一句话从哪来**：每个工具调用、命令、说的话，按规则变成一句短话（「读了 draft.md」「跑了 npm test：3 个失败」「写了 3 段」），
  不调用模型、不花 token、马上就有。长的回复只取第一句。**点开一条时**，再用主模型把这件事到现在做了什么概括成两三句，放在展开的顶上（点开一次概括一次，有新进展时可以刷新）。
- **放在哪**：经典桌面在右侧小组件那一栏的最上面（「正在做」一栏）。它**替换**现在程序坞左边的「正在做」托盘，便签替换程序坞右边的
  「做完的」托盘——同一件事只在一个地方（两个托盘都已拿掉）。一个窗口占满桌面、或者窄屏时，它缩成顶栏上一个光点，点开是整条。地图上：在左边分组卡片的下面（卡片的高度让出这块），样子跟着地图（古地图是墨字小卷，星图是星光字，未来是
  全息字）；地图没有顶栏，缩起来时是右下按钮那一排开头的一个光点。
- 减少动态效果时：不滚动，只换字。

### 3. 做完：便签和记录

- 一件事做完，它那一条收成一张**便签**留在「正在做」下面：标题、做成了没有（绿 / 红）、结果的一句话（stage_result 或报告的第一句）、
  结果的缩略图（第一张图、PDF 首页、网页截图），两个按钮：**看结果**、**擦掉**。
- **擦掉** = 看过了：从桌面上拿走，收进记录（就是现在的 markSeen / sessionSeen）。点「看结果」也算看过。
- **记录**是一个页面：所有智能体的工作——工作流的运行、会话、池子任务——在一张单子上，按**任务**、按**智能体**、按**天**分，能搜；
  每一条：做了什么、谁做的、多久、用量、结果文件、可以重放的过程。

### 4. 结果：查看器

- 现在运行页里的结果查看器提成整个桌面都能用的一个**查看器窗口**：便签、记录、运行页、会话、地图都用它打开结果。
- 打开的位置跟着东西走：一份文档 / 网页开一个大窗口；一张图、一段视频按它自己的比例；多个文件时左边一列文件。
- 会话做出的文件（它的文件夹里新建、改了的）也能在里面看。
- 保留已有的：写意见、从某一步带着意见重来、对照上一版。

### 5. 会话和 tmux / Zellij

- 常驻会话本身不变（结构化的进程，系统能读懂每一步）。另加一个**镜像**：`ruyix session attach <会话>`，在任何终端里实时显示这个会话的
  对话（人能读的样子），你在下面打字就是给它发消息。
- 每个常驻会话在一个 tmux 会话 `ruyix` 里有一个窗口（Zellij 里一个标签），跑的就是这个镜像。你在自己的终端 `tmux attach -t ruyix` 或
  打开终端应用，就能一个个切过去看、插话。
- 桌面上：「正在做」里会话那一条点开就是它的工作台；智能体页「会话」有每个会话的卡片；终端应用里能直接进 tmux 的那个窗口。

### 6. 消息连线图

- 一件事里有几个会话 / 智能体时，它的工作台顶上画一张**协作图**：每个智能体一个点（颜色同上），留言、交接是连线，每发一条消息就有一个
  光点沿线飞过去（地图上已经有这种流星）。点一条线看那几条消息。
- 数据就是现在的留言和交接，不新造。

### 7. 工作流里的「讨论」节点

- 新的人工步骤 `ask: 'chat'`（讨论）：到这一步运行停下，桌面上那一条变琥珀色、冒出一个聊天图标（也是一张便签）。点进去是和这一步的
  智能体的对话（开了会话的工作流：就在它的会话里，它记得前面做了什么）。
- 讨论完：「**可以了，继续**」——智能体把讨论定下的事写成一段，作为这一步的结果交给后面的步骤；或者「退回某一步重做」「停下」。
- 智能体也能在一步中间主动叫人讨论（一个工具，像现在的「请人拿主意」）：一样冒出聊天图标，那一步等着。
- 和已有的节点一起：审阅（看稿写意见）、拿主意（选一个）、填写、去做、结果（只给人看，不拦着）、留言板（智能体之间）、讨论（人和智能体谈）。

### 8. 样子

- 一套设计变量：颜色、字、圆角、玻璃、光——所有新东西都只用它们，跟着桌面、主题、地图换。深色里发光，浅色里是描边和墨色。
- 动的地方只有三种：滚动的字、光点、展开收起；都短而顺，可以关。
- 字号：歌词条里的当前行要能一眼读到（不比正文小），旧行变小变淡。

## 先后和分工

1. **数据先行**（`__ruyixWork` 的每一项）：
   - `lines`：最近几句，每句 `{ at（毫秒）, agent（这一项 agents[] 里的 id：颜色、名字从那里来）, text, kind: tool | say | wait }`，
     每个智能体最多 6 句，最新的在最后。
   - `outcome`（做完时）：`{ ok, text（一句话）, thumb?（同源的小图地址，约 320px；不放 data: 地址——整张单子每次都按 JSON 比较）,
     open?: { event, detail } }`。
   - 擦掉：单子加一个钩子——`set(source, items, { seen: ids => … })`，桌面调 `workRegistry().seen(id)`，由那一项的出处去记「看过」
     （运行：markSeen；会话：sessionSeen）。桌面不用知道出处。
   - 点开时的概括：每个出处给一个 `summarize(id)`（运行：workspace-ce，用账本；会话、池子任务：workspace-d0）。
   - 谁做：运行的 `lines` / `outcome` / `summarize`：workspace-ce；会话和池子任务的：workspace-d0；单子的 `seen` 钩子（shell 的
     work.js）：workspace-d0。
2. **歌词条和便签**（所有桌面、地图的样子）：workspace-15。
3. **讨论节点**（引擎、对话面板、主动叫人的工具）：workspace-ce。
4. **记录页和查看器窗口**：workspace-ce（会话那部分的数据由 d0 给）。
5. **tmux / Zellij 镜像、会话卡片、协作图的数据**：workspace-d0；协作图：workspace-15 做成 shell 的一个组件（`@ruyix/shell/collab`：
   `<CollabGraph agents={[{ id, kind, name }]} links={[{ from, to, at, text }]} />`，每条新消息一个光点飞过，点线看消息），各自的展开
   视图里放它，处处一个样子。
