# Ruyix：方案

2026-10-13 · Ethan 提的方向：像 Omarchy 那样，界面全部自己定、随时加应用、点开就能跑，同时有原生的智能体工作流；
智能体能改系统里的任何东西，但只在它自己的盒子里。最早写在 Pica 里（叫 Pica OS），2026-10-13 定名 **Ruyix**，
新起一个仓库，先做底座，应用以后再加（名字和约定见 [base.md](base.md)）。
§12 里三件待定的事都定了（2026-10-14）：也要能装别人的，先装 Linux 应用；先做外壳。

## 1. 想要的和不做的

想要的：

- 整个界面自己定，好看；主题、布局、快捷键都能改。
- 应用随时加，点开就跑；也可以说一句话，让智能体写一个新应用。
- 原生的智能体工作流：运行、审批、凭据隔离、账本，这些 Ruyix 已经有。
- 智能体能改系统，但只在自己的 microVM 里，碰不到 Mac。
- 成本低：不写内核、驱动、窗口系统。Linux 当内核，Mac 上的浏览器当显示器，dsh 当智能体运行时，Ruyix 写外壳、系统服务和应用。

现在不做：装到机器上替换 macOS（以后可选，见 §11）；多用户。

## 2. 分层（和 Omarchy 对照）

| 层 | Omarchy | Ruyix |
|---|---|---|
| 硬件 | 一台 PC | Mac |
| 虚拟化 | 没有，直接装在机器上 | macOS + Apple container + nookbox（凭据、网关、审计、端口、挂载） |
| 内核 | Linux | Linux（Apple container 的，在宿主上统一设置，不在镜像里） |
| 发行版 | Arch | `debian:trixie-slim`（`box/image/Dockerfile`），可换（§8） |
| 桌面外壳 | Hyprland 加菜单和脚本 | Ruyix 外壳（`core/shell`）：启动器、命令面板、主题，显示在 Mac 的浏览器里 |
| 系统服务 | systemd 等 | Ruyix core：工作流引擎、审批、连接器、账本；加 dsh：智能体循环、调模型、插件加载 |
| 应用 | Linux 软件 + 网页应用 | 领域包 + 网页应用 + 命令行工具；第 3 阶段起加 Linux 图形程序 |
| 智能体 | 没有 | 在盒子里干活；要 root 的事经主机上的 nookbox 做（§7） |

**dsh 不是内核。** 它提供智能体循环、模型调用、插件加载和网页框架，更像运行库加硬件抽象层。做内核该做的事的（调度运行、权限、
凭据、审计）是 Ruyix 自己的 core。所以应用只依赖 Ruyix 的接口，不直接用 dsh（§10）。

## 3. 已经有的

| OS 里的概念 | Ruyix 现在 |
|---|---|
| 进程 | 一次运行（run）：状态、步骤、日志，能暂停、恢复、中断（`resumeRun`） |
| 系统服务 | 工作台引擎（`core/workbench`） |
| 权限弹窗 | 审核卡：对外的动作都要批准 |
| 钥匙串 | 连接器（`core/connectors`）：凭据只在这里，智能体拿不到；box 模式下值在宿主保险库 |
| 系统日志和审计 | 带哈希链的账本；box 模式下还有 nookbox 的网络和进程审计 |
| 驱动 | 智能体池（`agent-hub`）：dsh、Claude Code、Codex、pi 各是一种运行时 |
| 应用 | 领域包：`definePack` / `registerPack` 注册工作流、页面、设置 |
| 桌面和启动器 | 外壳：首页（设置步骤、概览）、侧栏分组、统一设置、插件页、智能体提议改动（人点了才生效，可撤销） |
| 包管理 | `ruyix plugin add`、`ruyix upgrade`、`ruyix restart`（`busy()` 为空才重启） |
| 虚拟机 | box 模式：整个 Ruyix 跑在一个 microVM 里（[box.md](box.md)） |

## 4. 还缺的

1. **应用清单和权限**（§6）：现在领域包和系统在同一个 Node 进程里，视频包能读写任何文件、用任何连接。
2. **应用的完整生命周期**：装、卸、开、关、更新都在界面里走一遍。插件页现在只做了一部分。
3. **启动器当主界面**：首页是应用格子，点开是这个应用的全屏页面；侧栏退为正在跑的任务和通知。
4. **共享文件**：素材库和成片现在是视频包自己的；做成系统的文件服务，社交包也能拿成片去发。
5. **隔离**：只跑自己的应用时，同一进程加清单够用；要装别人写的应用，就要每个应用（或每次有风险的运行）一个盒子（§9 布局 B）。

## 5. 从 Omarchy 借的

- **一个命令面板管所有事**（Omarchy 是 `Super+Alt+Space`）：开应用、换主题、装应用、跑工作流、找运行。
- **一个颜色文件生成整套主题**：`core/shell/tokens.css` 已经是语义化的颜色变量，再加一层「主题文件 → 变量」，换主题只换一个文件。
- **键盘优先、页面内平铺**：在 Ruyix 自己的全屏页面里做，不改 dsh 的框架，不做窗口管理器。
- **网页应用当应用**：任何网站或工具包成一个应用图标；不允许被嵌进页面的网站，就另开窗口。
- **按住说话**：浏览器录音 → 宿主上 omlx 的 Qwen3-ASR → 文字进输入框或交给智能体（Omarchy 3.3 也加了本地听写）。

Ruyix 独有的：说一句话，智能体写一个新应用（一个领域包），dsh 的插件管理器原地加载，不用重启。

## 6. 应用清单（初稿）

放在每个包的 `package.json` 的 `ruyix.app` 里（`core/shell/package.json` 已经用 `ruyix.dsh` 记 dsh 版本，沿用这个位置）：

```json
{
  "ruyix": {
    "app": {
      "id": "video",
      "name": { "zh": "短剧推广片", "en": "Drama promos" },
      "icon": "clapperboard",
      "permissions": {
        "connections": [{ "id": "omlx", "why": "识别、配音" }, { "type": "baidupan", "level": "read" }],
        "files": [{ "path": "~/Movies/Ruyix", "access": "rw" }, { "path": "/workspace/dramas", "access": "r" }],
        "hosts": ["openrouter.ai"],
        "agents": ["codex"],
        "devices": ["mic"],
        "hostServices": ["encode"],
        "budget": { "monthlyCny": 50 },
        "system": false
      }
    }
  }
}
```

| 字段 | 意思 | 对应的 nookbox 策略（布局 B 时这个应用自己那个盒子的） |
|---|---|---|
| `connections` | 能用哪些连接（按编号或类型），只读还是能写 | 能用的凭据（`-s CONN_<ID>__<SLOT>`） |
| `files` | 能读写哪些文件夹 | 挂载（`--mount 宿主:盒子:ro/rw`） |
| `hosts` | 能访问哪些外部网站 | 出网允许清单（`allow`） |
| `agents` / 模型 | 用哪些智能体、模型 | — |
| `devices` | 经浏览器用的设备：麦克风、摄像头、录屏 | —（在你那边的浏览器里，不进盒子） |
| `hostServices` | 主机上开放的能力（§9 的设备代理） | 宿主端口（`host_ports`） |
| `budget` | 每月最多花多少 | — |
| `system` | 能不能请求改系统（§7）；能的话每次都要审核卡 | 主机上 nookbox 的窄接口 |

怎么落地：

1. 第 1 阶段只声明：装的时候显示给你看，界面上列出每个应用要了什么。
2. 第 2 阶段由系统服务把关：连接器拒绝清单外的连接，文件服务拒绝清单外的路径，box 模式下出网走网关。
3. 布局 B（每个应用一个盒子）时，清单原样变成那个盒子的 nookbox 策略，应用代码不用改。

## 7. 智能体改系统：配方和回滚

显示界面的系统，就是智能体在改的那个系统；改坏了 dsh 或 Ruyix，界面就没了。所以：

- **遥控在盒子外面**：宿主上的 nookbox 不依赖 Ruyix 的界面，随时能停、启、进去修（`nookbox exec`）、回滚。
- **系统改动写进配方，不直接改正在跑的系统**：
  - 系统软件包：`nookbox install`（在运行中的盒子里立即以 root 装，同时写进盒子的规格，重建时自动带上）。
  - 其他系统改动：改仓库里的 `box/image/`，打新标签 `ruyix:<版本>-<提交号>`，`nookbox update ruyix --image …` 切过去。
  - 回滚：`nookbox update ruyix --image <上一个标签>`。
  - 直接在运行中的系统里改的东西，换镜像时会丢；只有家目录那个卷保留。
- **智能体不拿 root**：macOS 上 Apple container 的出网规则在 VM 里由 root 执行，盒子用户有 sudo 就能改写自己的出网规则
  （nookbox 已知限制 L5，所以 nookbox 默认不给 sudo）。因此智能体以普通用户干活；要 root 的事由它提出 → 审核卡 → 主机上的
  nookbox 执行。Linux 上 krun 的出网规则在 VM 外，root 也改不了，那里可以放宽。
- **窄接口**：盒子现在连不到 nookbox 的 API（7700，网关拒绝宿主自己的地址，实测）。要开一个只针对这个盒子、只允许
  「装包、换镜像、回滚」的口子，每次都要审核卡批准，其他照旧拒绝。
- **内核不在盒子里改**：Apple container 的内核在宿主上统一设置，所有盒子共用一个，不在镜像里。盒子里能改的是内核之上的一切。
- **记账**：每次系统改动进账本：改了什么、谁批准的、镜像标签从哪个换到哪个。

## 8. 系统底座：先留在 Debian，以后可能用 Nix

现在是 `debian:trixie-slim`，加上「配方 + 镜像标签 + 切换回滚」，已经有了 Nix 八成的好处（能从源码重现、整体切换、能回滚）。

**Nix 的好处**：整个系统由一份配置文件描述；每次改动是一个新版本，一条命令退回；智能体改系统就是改那份文件，审核卡上能直接
显示改了哪几行；同一软件多个版本并存，临时用一个工具不留痕迹。比现在多出来的是细粒度：装一个包、退一个改动只要几秒，不用重打
整个镜像。

**代价**：要学 Nix 的配置语言；很多下载即用的程序要额外处理才能跑（Nix 的目录结构和普通 Linux 不同），我们用到的
Playwright 自己下载的 Chromium、npm 包里的预编译程序、Codex 的可执行文件都是这一类；磁盘占用更大，要定期清理；完整的 NixOS
在 Apple container 里很别扭（它用自己的启动方式，不会像真机器那样把 NixOS 整个启动起来），适合配完整的虚拟机。

**性能**：运行速度一样（同样的内核，正常编译的程序），没有损失也没有提升；只是磁盘占用更大，应用一次改动要几十秒到几分钟。

**定的做法**：现在不换。第 2 阶段智能体经常改系统时，先在 Debian 盒子里用 Nix 管软件；完整 NixOS 和「换成完整虚拟机」一起考虑。
换成 Arch 只在要直接复用 Omarchy 的主题、脚本，或者要 AUR 里的软件时才值得：滚动更新、手工调教，和「智能体改、出错要能退」相反。

## 9. 硬件

现在的 microVM（Apple container）只给 CPU、内存、磁盘、网络、共享文件夹；没有声卡、显示器、GPU、USB。

**你这边的设备经浏览器进来**：麦克风、摄像头、录屏、通知、剪贴板、选文件（Chrome 还有 USB、串口、蓝牙）。这些要求页面是
https 或本机地址，`127.0.0.1:3180` 和 `127.0.0.1:3080` 都满足。box 模式下声音在 Mac 上录、经端口进盒子、由宿主的 omlx 识别。
浏览器做不到的：页面不在前台时、全局快捷键、管别的程序和系统设置。要这些，就给 Ruyix 套一个很薄的原生外壳（比如 Tauri 做的
Ruyix.app：全局快捷键、菜单栏图标），可选。

**让盒子用上主机的硬件**：

| 办法 | 能用到的 | 隔离 | 性能 | 成本 |
|---|---|---|---|---|
| A. 自己写虚拟机启动器（直接用苹果的虚拟化框架，或给 nookbox 加一种运行方式） | 麦克风和扬声器（虚拟声卡）、虚拟显示器（只有 2D）、U 盘 | 强 | 声音、显示都还行 | 中 |
| B. libkrun / krunkit（Podman 在 Mac 上用的 microVM） | GPU，走 Vulkan，再翻译成 Metal | 强 | GPU 计算能跑一部分（如 llama.cpp 的 Vulkan 后端），比原生慢 | 中，要换运行时 |
| C. macOS 虚拟机 | GPU 加速（Metal）、声卡 | 强 | GPU 还不错 | 重：几十 GB、启动慢，同时最多两个 |
| **D. 主机上的设备代理（推荐）** | 一项项开放：硬件视频编码、本地模型、截屏、操作 Mac 上的程序 | 强，每项单独授权、进审计 | 原生，活在主机上干 | 低 |
| E. 不用虚拟机，智能体进程用 macOS 自带的沙箱 | 全部 | 弱，和主机共用内核 | 原生 | 低 |

**苹果虚拟化框架的上限**：Linux 虚拟机拿不到 GPU 的 3D 和计算加速、神经网络引擎、摄像头、任意 USB 直通、蓝牙和 Wi-Fi，谁来写
都一样。苹果的框架里也不能自己加虚拟硬件，能加的只有盒子和主机之间的通信通道，那就是 D。要真写虚拟硬件，得在 QEMU 或
libkrun 里写虚拟设备的后端，不值得。

**D 怎么做**：主机上一个小程序，盒子经宿主端口（`host_ports`，和现在调 omlx 一样）找它；每项能力是一个接口，应用在清单里声明
（`hostServices`），敏感的（截屏、操作 Mac 上的程序）每次走审核卡；请求进 nookbox 的审计。第一项做**硬件视频编码**：盒子写好
合成方案（`render-tmp/compose.json`），主机用 ffmpeg 的 VideoToolbox 编码器读写共享文件夹出片（盒子里的路径要换成宿主的路径），
比盒子里用 CPU 编码快得多。

以后要在盒子里直接放声音、跑带图形界面的程序，再考虑 A；要 GPU 直接进盒子，再看 B。

## 10. 约束

1. **dsh 是别人的，还是预览版**（0.2.0-rc.2）。应用只依赖 Ruyix 的接口（`registerPack`、工作台服务、连接器服务），不直接用 dsh；
   现在基本做到了（应用只注入 `ruyixWorkbench` 和 `connection`），要保持。外壳替换 dsh 界面的地方越多，dsh 升级越容易坏，
   所以「像 OS」的界面做在 Ruyix 自己的全屏页面里。长期看，可以用自己的智能体运行时换掉 dsh。
2. **core 保持通用**：系统服务里不出现「短剧」「小红书」这类词（`check.mjs` 已经在查）。
3. **同一个进程，没有代码层面的隔离**：只跑自己的应用没问题；装别人的应用之前，必须先有布局 B。
4. **单用户。**
5. **Windows 上没有 box 模式**（nookbox 只有 macOS 和 Linux；macOS 要 26 以上）。
6. **microVM 里没有 GPU**：渲染只能用 CPU（直到 §9 的硬件编码做好），本地模型留在宿主的 omlx 上。

## 11. 布局和阶段

**布局**：

- **A（现在）**：整个 Ruyix 在一个盒子里，nookbox 在宿主上管凭据、网关、审计。
- **B（以后）**：Ruyix 在宿主或一个常驻盒子里；有风险的活（智能体执行代码、服务端浏览器、别人写的应用）每次开一个用完就删的盒子。
  盒子里不能再开虚拟机，所以由宿主上的 nookbox 开，经 §7 的窄接口请求。

**阶段**：

1. **外壳**：启动器（应用格子）、命令面板、主题文件、按住说话、应用清单（只声明）。做完的样子：首页是应用格子；一个快捷键打开
   命令面板，能开应用、换主题、跑工作流；换主题只换一个文件；视频、社交、连接器、智能体池各有清单。
2. **系统能力**：一个「系统」应用，智能体请求装软件、改配置，走审核卡，写进配方；一键回滚（列出镜像标签、切换）；§7 的窄接口；
   §9 设备代理的第一项（硬件视频编码）；清单开始由系统服务把关。
3. **虚拟桌面**：盒子里加一个虚拟显示器，画面推到浏览器；Linux 图形程序以窗口出现在 Ruyix 里，智能体看截图操作它们
   （把现在小红书用的服务端浏览器实时画面推广开）。
4. **以后可选**：换底座（Nix 或 Arch）；布局 B；装到一台 Linux PC 上开机进全屏浏览器（装在机器上的 Ruyix，前面的都不用重写）；
   自己的运行时换掉 dsh。

## 13. 桌面（2026-10-14 做进外壳）

原型第二版（中性材质、外观 / 强调色 / 壁纸分开选、GPU 壁纸）Ethan 认可，做法：

- dsh 一次只显示一个页面，外壳把它变成**一个窗口**（标题栏拖动、边缘调大小、关闭回到桌面、最小化、最大化），放在壁纸上；
  顶栏、程序坞、⌘K 命令面板、右侧的常驻对话、通知都画在 dsh 的覆盖层里（portal 到 body），不改 dsh 的框架代码，只用 CSS
  把它的框架移进窗口。
- **程序坞**按侧栏的分组排页面；Ethan 指出原型里图标悬停、点击的动画会跑出程序坞、碰到旁边的图标：现在程序坞留出足够的内边距，
  上浮只在边距里，图标间距加大，名字画在程序坞外面。
- **别的窗口**：插件可以在页面窗口旁边再开窗口（`window.__ruyixDesk.open`），和页面窗口一起排前后，程序坞里各有一个图标。
  Linux 图形应用就是这样出现的（§14）。
- 外观存在 `desktop.json`（界面：桌面 / 经典侧栏，壁纸，强调色，动态，半透明），是一个 surface：人在设置里改，智能体只能提议。

  吉祥纹样，寓意同心。黑底朱红 #E0452F，装成应用的图标带一点光。和雷诺新标、「链接」图标拉开（不穿插、中间实心）；正式检索还没做。
- 补回 Aviary 原型里的几样（2026-10-19，Ethan 看了原型：「运行和智能体的一些显示，还有需要你的一些显示，这些都挺好的」，「都补上吧，
  先做设计稿」，设计稿定了以后做）：桌面上四个小组件，默认放上桌面（自己摆过的桌面也放一次，desktop.json 的 widgetsOffered 记着，拿掉
  的不回来）——「任务」：进行中的几件，每件一根进度条，拉大多显示几件，右上角放大成一个能拖能改大小的任务小窗，像原型的运行窗口
  （「任务是一个比较大的页面，但是可以打开一个小的」）；「智能体」：池里每个在做什么，空闲的最近一次做了什么；「今天」：今天动过的
  任务、模型花费、tokens 和近 12 小时的曲线（用量按小时记：workbench 的 lib/usage-hours.js）；「盒子」：正常不正常、今天出网、拦下几次。
  顶栏加盒子的盾牌。任务页在做和等你的几件下面一根进度条：工作流按做完几步算，不知道一共几步的就是一段流动的光，不编一个百分比。
  收件箱补「已处理」。花费先用美元，设置里能换人民币（「先用美元，可以在 settings 里面改这个币种」）。
- **全屏**（2026-10-15，Ethan 问「在浏览器里能不能真正全屏，像真正的桌面一样」）：顶栏右边的全屏按钮、Ruyix 菜单、⌘K 和
  ⌃⌘F，用浏览器的 Fullscreen API 把整个页面铺满屏幕，浏览器的标签栏、地址栏和 Mac 的菜单栏都让开，只剩 Ruyix 自己的顶栏。
  浏览器只允许点击或按键时进入全屏，所以不能打开页面就自动全屏。Chrome 和 Edge 全屏时还会锁住 ⌘W、⌘T、⌘N 和 Esc
  （Keyboard Lock API），这些键交给 Ruyix 和里面的应用，不会关掉标签页；Esc 用来关菜单，按住 Esc 才退出全屏。
  Safari 和 Firefox 没有键盘锁定，按一下 Esc 就退出。
- **装成应用**：页面带了 web app manifest（`core/shell/app.js`，图标是新标志画成的 PNG）。Chrome 的「安装 Ruyix」或
  Safari 的「文件 → 添加到程序坞」会在 Mac 的程序坞里放一个 Ruyix 图标，打开就是一个没有地址栏的独立窗口；再按 ⌃⌘F
  全屏，Ruyix 有自己的一个桌面空间，三指左右滑可以在 Mac 和 Ruyix 之间切换。

**常驻对话**：单人版，一条保存下来的对话，在任何页面右侧打开；对话里能画看板、提议运行（人点了才开始）。

**语音输入**：按住右边的 ⌥ 说话（或点顶栏的麦克风），松开后文字进光标所在的输入框；没有输入框时打开 ⌘K。浏览器录 16 kHz
WAV，外壳经一个连接（http 类型）发给兼容 OpenAI 的 `/audio/transcriptions`——默认就是 Fonos 用的那个：宿主上 omlx 的
Qwen3-ASR，凭据留在连接器里。Fonos 本身不装进盒子：盒子里没有麦克风也没有真实屏幕；在 Mac 上开着 Fonos，它照样能往
Ruyix（浏览器里的页面）里输入。

## 14. Linux 应用（2026-10-14 开始）

- **装**：nookbox 新加了盒子自己的安装接口 `POST nookbox.internal/v1/packages`：apt 以 root 从镜像自己的软件源装，
  记进盒子的规格（重建后还在），盒子用户始终没有 root、只能挑 Debian 的包名，每次都进审计；默认关，宿主上
  `nookbox update ruyix --self-install true` 打开。应用中心（`@ruyix/apps`）点「安装」就走这个接口。
- **图形应用**：每个应用一个虚拟屏幕（TigerVNC 的 Xvnc + matchbox 窗口管理器），画面经 Ruyix 自己的端口（dsh 的 WebSocket
  路由，用 dsh 的登录校验）送到浏览器，用 noVNC 画在桌面的一个窗口里；窗口大小变了，虚拟屏幕跟着变。没有额外端口。
- **命令行工具**（ffmpeg、pandoc、yt-dlp……）：装进盒子，智能体直接用。
- **外观**（2026-10-15，Ethan 觉得这些应用「特别丑」，问是不是自己写的）：它们本来就是原生 Debian 程序；丑是因为盒子里
  没有桌面环境，没人告诉它们主题、图标和字体，所以只剩 GTK 最简陋的默认样子：DejaVu 字体、放大发虚的旧图标、永远浅色。
  现在每个应用启动时都会拿到一个桌面本该给它的设置：Adwaita 主题、Papirus 图标、Inter 字体（中文回落到 Noto Sans CJK，
  代码用 JetBrains Mono），深浅跟着 Ruyix 页面走；GTK 4 应用改用软件渲染（虚拟屏幕没有 OpenGL，否则窗口一片白）。
  应用中心先列 GNOME 自己的新版应用（GTK 4 / libadwaita）：控制台、文件、文本编辑器、计算器、Papers、Loupe；LibreOffice
  改用 GTK 3 的界面（原来是它自己画的小号 X11 控件），并且固定用浅色（深色主题下它的图标看不清）。
- 以后：智能体看截图操作这些图形应用（§11 第 3 阶段）；声音、GPU 不在这一步。

## 15. 定制（2026-10-16）

Ethan：这个系统应该体现 customize 的作用和效果，而不是说 agent OS；先做 Omarchy 那样的三件事。名字先改成 Agnos，
同一天又定为 Ruyix（「如意」，他有 ruyix.org 这个域名）；图标随之换成一柄如意。

- **一套主题管所有东西**（`desktop.js` 的 `THEMES`）：壁纸、强调色、窗口底色（`TINTS`：中性、暖、冷，换的是底色、线条和
  文字的颜色，每种文字在每种底色上对比度都不低于 4.5:1）、圆角，外加浏览器的深浅色。选主题时写进 `desktop.json`，
  `theme` 记着是哪个；之后单改一项，主题保留，选择器里标「改过」。Linux 应用：深浅跟着页面，GTK 4 / libadwaita 应用的
  强调色用 `ADW_DEBUG_ACCENT_COLOR`（盒子里没有设置门户，libadwaita 1.6 起读这个变量）。
- **一个能直接改的文件**：`~/.ruyix/desktop.json`。页面每 3 秒问一次有没有变，变了就重画；手改坏了不会突然回到默认，
  而是保留上一次正确的样子，并弹出哪里错了（`surfaces.js` 的 `pageNow`）。设置页底下显示文件的位置。
- **用命令改桌面**：`ruyix desk`（`bin/ruyix-desk.mjs`）读、列主题和键、提议改动。和 `ruyix changes` 一样从不直接应用：
  智能体的 shell 也能跑这个命令，所以改动要等人点「应用」（`--wait` 可以等结果）。Omarchy 的 `omarchy theme set` 是直接改；
  这里多一步确认，是因为改桌面的往往是智能体。
- **给智能体的技能**：`core/shell/skills/ruyix-desktop/SKILL.md`，注册成 Agent Hub 的技能包 `ruyix`；盒子里 `ruyix start`
  把它链接进 Claude Code、Codex 和共用的技能目录（只换链接，不碰同名的真目录）。和 Omarchy 把自己的技能链接进
  `~/.claude/skills` 是同一个做法；不同的是，Ruyix 的智能体本来就在桌面里。

## 16. 看得见、改得了的工作过程（2026-10-17）

Ethan：工作流要有版本（Git，所有工作流通用），过程要很可视化、能显示证据和记录，关键步骤能回退、能从某一部分重新开始，
也能在对话或侧栏助手里控制；再加一些 OS 层面的呈现，让人理解事情是怎么做成的。本质是让智能体的工作流更容易用、更容易
理解过程、更容易控制。第一个用上这些的是 Plume（多平台发布，`packs/plume`）。

- **版本**：每个运行一个影子 Git 仓库，每一步之后一个版本；回到任何一步之前、改了结果从下一步接着跑、带着意见重跑某一步
  （`run-versions.md`）。
- **过程**：运行页面的「过程」——步骤流程图（正在做的一步发光，等你的一步琥珀色，跑过几轮标 ↺）、「现在」一栏（哪一步、
  谁在做、多久、最后一条记录）、每一步的实时记录和改了的文件、时间图（每一步什么时候做、等了你多久）。「文件与版本」看
  每一版改了什么、单个文件的历史、两版的差别，直接改。
- **看得见、能接手的浏览器**：步骤或卡片打开的浏览器，画面实时出现在页面和卡片上，人直接点、打字，做最后一下（小红书的
  「发布」就是人自己点的）。
- **在对话里控制**：助手能读版本和文件；回退、改文件、接着跑都只出卡片，人点了才执行。
- **OS 层面**：顶栏托盘里的「正在做的事」（有在跑的就转圈，有等你的就是琥珀色的手和数字，点开是列表）和同名的桌面小部件；
  新建运行时先看「这个工作流怎么做」：每一步谁做、哪里等你、什么会发出去、哪一步联网。外壳的托盘是通用的
  （`window.__ruyixTray`），以后别的插件也能放。
