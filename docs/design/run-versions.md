# 运行的版本、回退和修改（设计）

2026-10-17 · Ethan：工作流要有版本（用 Git，所有工作流通用），关键步骤能回退到某一步，整个过程容易编辑，能从某一部分
重新开始；也能在对话或侧栏助手里控制这些。这是三步里的第一步（接着是可视化的运行页面，然后是 Plume 的发布工作流）。

**状态（2026-10-17）：已做完。** 代码在 `core/workbench/lib/versions.js`（版本）、`lib/engine.js`（每一步前后提交、回退、修改、
接着跑）、`src/process.jsx` / `src/versions.jsx` / `src/diff.jsx`（运行页面的「过程」和「文件与版本」）；检查在
`versions-check.mjs`。和下面的设计不一样的地方记在最后「做的时候改了的」。

## 现在有什么

- 每个运行有自己的文件夹（`runs/<id>/work`），或者人指定的文件夹（「任务」工作流的 `folder`）。
- 每一步做了什么都记在账本里（带哈希链的证据），步骤有 `history`。
- `resumeRun({ from })`：从某一步重新跑，结束了的运行也可以。但**文件不会回到那一步之前的样子**：后面步骤写的文件还在，
  重跑的步骤看到的是「未来」的文件。
- 没有文件的版本，也看不到某个文件在哪一步变成什么样。

## 要加的

### 1. 每一步一个版本

- 每个运行有一个**影子 Git 仓库**：`runs/<id>/versions.git`，工作区是这个运行的文件夹
  （`git --git-dir=… --work-tree=…`）。不在文件夹里放 `.git`，所以人指定的文件夹（可能本来就是一个 Git 仓库）不受影响，
  它自己的 `.git` 不会被收进来。
- 运行开始时提交一次（「开始」），每一步结束（成功、失败、被退回都算）再提交一次，提交信息是「第 3 步 改写：…」，
  步骤记下这次提交（`stage.commit`）。没有变化的步骤不产生提交，只记下当时的提交。
- 不收进来的：文件夹自己的 `.gitignore` 里写的；单个超过 20 MB 的文件（记成「太大，没有留版本」）；`node_modules` 一类。
- 一个文件的历史：`git log --follow`；某一版的内容：`git show <提交>:<路径>`；两版的差别：`git diff`。

### 2. 回到某一步

- 「从这一步重新开始」：先把文件夹恢复到**这一步开始之前**的样子（上一步的提交），再 `resumeRun({ from })`。
- 恢复不抹掉历史：做法是把那一版的文件写回文件夹，再提交一次「回到第 3 步之前」。后来的版本都还在，随时能看、能比较、
  能再拿回来。账本也一样，只增不删。
- 人指定的文件夹：恢复前列出会被改回去的文件，人确认后才动（那可能是人自己的代码）。

### 3. 改某一步的结果，再接着跑

- 在运行页面里打开某一步产出的文件（比如原稿），直接改，存下来就是一个新版本（「人改的」）。
- 「从下一步接着跑」：后面的步骤用改过的文件。
- 也可以给意见让智能体改（「这一段改短」）：那一步带着意见重跑，其余不动。

### 4. 在对话里控制

助手多几个工具，读的直接答，动东西的都先变成卡片等人点：

| 工具 | 做什么 |
|---|---|
| `workbench_run_versions` | 一个运行的版本：每一步的提交和改了的文件；给了路径就是这个文件的历史 |
| `workbench_run_file` | 某个文件在某一版的内容，或者两版的差别 |
| `workbench_run_rewind` | 提议「回到第 N 步重新开始」（卡片上写清会改回哪些文件） |
| `workbench_run_edit` | 提议改某个文件的内容（卡片上是差别） |
| `workbench_run_continue` | 提议从某一步接着跑（可以带意见） |

### 5. 界面（第二步「可视化的运行页面」里做足）

- 每一步旁边一个版本号；点开看这一步改了哪些文件、差别是什么。
- 文件列表里每个文件有「历史」：一条时间线，每个点是一步，点开就是那一版。
- 每一步的菜单：「从这一步重新开始」「改这一步的结果」「比较」。

## 不做的

- 不把版本推到任何远端（运行文件夹里可能有凭据、草稿）。以后要推，单独做「导出到仓库」。
- 不改账本的结构：版本是文件的事，账本是过程的事，两边用提交号互相指。

## 做的时候改了的

- 一步**开始前**也看一次：上一个版本之后文件夹被改过（人在外面改的、步骤之外的工具），就先提交一个「步骤之外的改动」，
  这样「回到这一步之前」回到的正是这一步看到的样子。每一步记下 `version.base`（开始前）和 `version.commit`（结束后）。
- 被停下的步骤也提交一次（「被停下」），它写到一半的文件不会混进下一步的版本里。
- 回退时，人在那之后手改的内容一起被撤掉，后面的步骤也不再被告知那次手改。
- 改文件：运行正在等人（比如等你审稿）时也可以改，答复之后后面的步骤就用改过的文件；有步骤正在干活时不让改。
  经过文件夹里指向外面的链接的路径不写。
- 独立复查之后加固的（2026-10-17）：
  - 回退不会弄丢没进版本的东西。被 `.gitignore` 排除的、超过 20 MB 的、自带 Git 的文件夹，只要挡在回退的路上
    （会被覆盖、删除，或者它所在的文件夹要变回文件），就先挪到 `runs/<运行>/kept/<时间>/`，预览里单独列出来。
  - 预览不提交、什么都不改（用一个临时索引算出文件夹现在的样子）。回退带着预览时的样子去执行，文件夹在这之后变过就拒绝，
    让人重新看。
  - 文件夹里出现自带 Git 的子文件夹（agent 跑了 `git init`、`cargo new`）：留在版本之外并列出名字，版本照常做；
    Git 真的失败时，版本关掉并写明原因，不会悄悄地每一步都没版本。
  - 路径：任何大小写、带尾点或空格、带可忽略字符的 `.git` 都拒绝；经过链接走到文件夹外的不读不写。影子仓库的 hooks
    和 fsmonitor 永远关着；文件夹包住工作台自己数据的不让用。
  - 同一个文件夹的 Git 操作排队（不同运行也一样）；另一个运行正在用这个文件夹时，不让回退和修改。
  - 人改文件：先把还没进版本的改动单独存一版，再只提交这一个文件；编辑从文件夹里的这一份开始。
  - 停下运行后，等智能体的任务真的结束再回退；回退、接着跑、归档都会关掉这个运行开着的浏览器。
- 助手多了一个读工具 `workbench_run_file`（读内容、看差别分开，比一个工具几种用法清楚）。
- 运行页面：「流程」改名「过程」，新增「文件与版本」；「账本」改叫「记录」，记录里的「关口」改叫「步骤结果」。

## 检查

- 一个运行三步，每步写文件：三个提交，每步记着自己的提交；文件历史对得上。
- 回到第 2 步：文件夹和第 1 步结束时一样，第 2、3 步重跑；之前的版本还在。
- 人指定的、本身是 Git 仓库的文件夹：它的 `.git` 不被动，影子仓库照常工作。
- 改结果再接着跑：后面的步骤读到改过的内容。
- 助手的工具：动东西的都只出卡片。
