# 智能体任务：这台 OS 上所有工作的核心（设计）

2026-10-18 · Ethan：智能体在这台机器上做的任何事都是一个**任务**——从最开始的输入（打字、语音、定时、工作室的一条）到最后的
输出，中间可能有几次交互、几个中间结果；输出之后让人确认这个结果可以了，这个任务才算完成；之后可以归档或删除。任务有长有短：
一次问答、一个常驻会话里的一段活、池子里的一个任务、一个工作流的运行。除了工作流，任务是另一个核心，要有任务管理。「记录」
升级成两样：智能体工作的**状态跟踪**，和**作品集**——智能体做出来的所有结果，只读地呈现，每一件都能找回是哪个任务（哪次对话、
哪个会话、哪次运行）做的。

同时他看到的几个问题：桌面上「收件箱」一直挂着「为什么每个人都需要一个 agent OS」那次运行早就处理过的审批；主智能体那块显示的
东西太少，又在右边不显眼的地方，组件也不能拖；让它「打开 YouTube」没反应；回答都是 Markdown，应该像上游那样在对话里生成界面
控件——问天气给一张天气卡，每次交互最后都要给人一个看得见的结果。

他定的（2026-10-18）：

- **什么时候算完成**：分情况。一问一答（问时间、问天气）回答完就完成；做出了东西或改了东西的（文件、稿子、帖子、设置），停在
  「待确认」，人点「好了」才完成，也可以说「再改」。
- **打开网页**：在他自己的浏览器里。回答里给一张卡片，点一下在新标签页打开（浏览器不让网页自己弹新标签，所以要点这一下）。
- **主智能体**：在底栏上方一条，平时一行（听到什么、在做什么），点开往上展开成对话和卡片。桌面上所有组件都能拖动、改大小。
- **作品集**：所有做成的结果——文件、稿子、发出去的帖子、报告、图片、对话里有用的回答——每件链回它的任务。

## 盒子里看到的（2026-10-18）

1. **一直挂着的**：主窗口停在「收件箱」，下面「最近处理过的」一直列着那次运行早已执行的两张审批卡。处理过的东西不该在收件箱里。
2. **「打开 YouTube」没反应**：主智能体（Claude Code）两次都调了它自带的「问用户问题」工具——我们的界面不显示这种提问，人看到的
   就是没反应；更早一次它说「这台机器没有浏览器」（智能体浏览器其实在）。
3. **回答是 Markdown**：问天气、问时间回的是表格和列表。对话里能画东西的只有 `workbench_ui`（从上游带来的：数据看板——计数、
   表格、趋势），没有天气、链接、选择这类卡片，主智能体也没用它。
4. **主智能体那块**在右边一列最下面，只有「听到」和最近几件做过的事。
5. 日期算错一天（已由 workspace-ce 修：每条消息前带上人那边的当前时间和时区，00e4360）。

## 任务

**一个任务**：人要智能体办的一件事，从它被提出（一句话、语音、定时到点、工作室的一条记录、别的智能体交过来）到人接受结果为止。
中间的往来——追问、审批、审阅、「再改」——都还是这个任务。

| 来源 | 一个任务是 |
|---|---|
| 对话（打字、语音、⌘K） | 人的一次请求和它引出的工作；接着问同一件事还是这个任务，换了件事就是新任务 |
| 常驻会话 | 交给它的一段活（一条消息起，到它交回结果） |
| 池子（组长分活） | 一个 job |
| 工作流 | 任务本来就有（`lib/tasks.js`）：一次性的或定时的，每跑一次是一个运行 |
| 工作室 | 从一条记录开始的那件事（Plume：写一条），记录和任务互相能找到 |

**状态**：在做 → 等你（提问、审批、审阅）→ 待确认（结果出来了）→ 完成；也可能没做成、停下。完成的、没做成的、停下的都能**归档**
（不在眼前，记录里还在）和**删除**。一问一答没有产出、没改东西，回答完自己就完成。

**产出**：每个任务做出的东西——文件、稿子、帖子（链接）、报告、图片、一张回答卡片——各自记下是哪一步、哪个会话或运行做的。作品集
就是所有任务的产出。

**和现在的关系**：工作台的任务（`lib/tasks.js`，任务 / 运行）扩成这里的任务，不另起一套；「正在做」的歌词条和便签、收件箱、
记录、工作室的成品，都是任务的不同视图。已有的数据（运行、会话、池子的 job、对话）挂到任务上，不搬家。

## 任务中心和作品集（「记录」升级）

- **任务中心**：所有任务，按状态分（在做 / 等你 / 待确认 / 完成 / 归档），能按来源、智能体、工作室、时间筛。点开一个：它的经过
  （对话、步骤、审批、智能体之间的消息，按时间）、它的产出，和「好了 / 再改 / 归档 / 删除」。
- **作品集**：只读。所有产出的缩略图墙，按类型、工作室、时间分；点开用查看器窗口看；每件写着是哪个任务做的，点一下到那个任务。
- **收件箱**只放等你的；处理过的到任务中心。

## 回答要看得见：卡片

每次交互最后给人一个看得见的结果，不只是一段文字：

- **卡片**：天气、时间、链接（打开网页）、视频、列表、表格和图表（已有的看板）、选择（要问人的时候）、确认（好了 / 再改）、
  文件、任务。主智能体用一个工具 `ui_card` 出卡片：描述先检查，不对就退回原因；画在对话里、主智能体那条上，也能钉到桌面。
- **打开网页**：一张链接卡，点一下在人的浏览器新标签页打开。
- **要问人的时候**：出一张选择卡，人点一个就是回答；Claude Code 自带的「问用户问题」不给主智能体用。
- 技能里写：能用卡片的地方用卡片收尾，文字只说一两句。

## 桌面

- **主智能体**：底栏上方一条。平时一行：听到什么、在做什么、等你什么；点开往上展开：这次对话、它出的卡片、在做的任务。
- **组件**：都能拖动、改大小，位置和大小记在 `desktop.json`。
- **收件箱**不常驻，只在有等你的东西时提醒。

## 分工

- **workspace-ce**：任务的数据和接口——`lib/tasks.js` 扩成通用任务（来源、状态、产出、好了 / 再改 / 归档 / 删除、一问一答自动
  完成）；对话里的请求成任务，运行挂在任务上；任务中心和作品集的数据（任务列表、经过、产出索引）；收件箱只留等你的；主智能体
  不用「问用户问题」，对话里接住选择卡的回答。
- **workspace-15**：任务中心页、作品集页；桌面——主智能体那条、组件拖动和改大小、收件箱不常驻；卡片的样子（和桌面一致的
  主题、深浅色）。
- **workspace-d0**：卡片——描述格式和检查、渲染组件（`@ruyix/shell/cards`，对话、主智能体那条、桌面共用）、主智能体工具
  `ui_card`、常用卡（天气、时间、链接、视频、选择、确认、文件、任务）；打开网页；会话、池子任务、工作室接到任务上（agent-hub、
  studio）；主智能体的任务工具（看任务、好了、归档）和技能。

## 先后

1. 同时开始：任务的数据和接口（ce）、卡片的格式和渲染（d0）——各自先把接口发到 main。
2. 各来源接到任务上：对话、运行（ce）；会话、池子、工作室（d0）。
3. 任务中心、作品集、桌面（15）。
4. 主智能体：卡片收尾、任务工具、技能（d0）；在盒子里用真模型走一遍：问天气给天气卡、「打开 YouTube」给链接卡、写一条稿子
   停在待确认、点「好了」进作品集。
