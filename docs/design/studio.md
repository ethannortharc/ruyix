# 工作室：把一件端到端的事串成一条线（设计）

2026-10-18 · Ethan：评审 Plume（多平台发布）的工作流，想怎么让它更好用。在过程中再抽象出一个东西——我们自己的、智能体的
「应用」：把相关的上下文、信息、历史、材料的管理，和智能体、工作流结合起来。比如「Plume 发布」这个应用：用已有的工作流，管理
相关的材料、历史、信息；从它进去，有它自己的界面和呈现，但内容都是别处已有的——更多是一个视图，加上引用和操作，增加使用的
便利。以后会有很多这样的东西：智能体的工作是横向的（整个系统），它是纵向的，把一件端到端的事拎出来串成一条线。存储、视图、
怎么呈现这些中间部分要做成通用的、能复用；要有一个创建它的东西，和一个操作它的技能。名字别和应用中心的「应用」混。

他定的（2026-10-18）：

- 叫**工作室**（Studio）：「Plume 工作室」。
- **先做 Plume 工作室当样板，同时把通用部件抽出来**；第二个工作室验证能直接复用。
- 小红书发布**改用共用的智能体浏览器**（docs/design/browser.md）：他在浏览器里登录一次，不再单独扫码。
- Plume 的账号设定**搬进工作室的「设定」页，支持多个账号**（人设），不再在设置里手写 JSON。

## Plume 现在的流程，和用起来的问题（评审）

流程（`packs/plume`）：收下请求 → 调研（可选）→ 原稿 `draft.md` → **人看原稿** → 改写成各平台的稿子 → 卡片和封面 → **人看各平台
的稿子**（手机预览、能直接改）→ 每个平台一张**发布卡片**（X 接口、小红书在浏览器里填好等人点发布、公众号复制粘贴）→ 报告。
每一步有记录、有版本、能回退；发出去之前都要人批准。流程本身是好的，问题在它四周：

1. **入口太深**：要发一条，得去工作台 → 新建任务 → 选「多平台发布」→ 填表。没有一个「写一条」的地方。
2. **账号设定藏在 JSON 里**：定位、风格指南、品牌色、署名、各平台限制在 `settings.packs.plume`，每次写稿都用，却没有表单，也只有一个账号。
3. **素材每次从零开始**：图片每次上传；以前的调研、原稿、做好的卡片散在各次运行的文件夹里，没有素材库可挑。
4. **历史靠翻运行**：发过什么、发到哪、链接在哪、哪条卡在哪一步，没有总览。
5. **缺的东西**：选题清单（想写的先记下，以后一键开写）、排期发布、发出去以后的数据。
6. **小红书单独一套登录和浏览器**：现在有了共用的智能体浏览器，应改用它。

## 工作室是什么

- **一条线**：某一类事从头到尾——想写什么（选题）、怎么写（工作流）、谁来写（智能体）、用什么写（素材、设定）、写成了什么、
  发到了哪（成品、历史）、什么时候发（排期）。
- **它自己几乎不存东西**：工作流、运行、智能体、会话、文件都是已有的；工作室存的是**引用**（这条成品是哪次运行做的、用了哪几张
  素材）和**它自己的几类记录**（选题、账号设定、排期）。
- **它有自己的首页**：从导航、地图、⌘K 进去，看到的是这条线上的东西，不是整个系统。
- **和智能体的关系**：智能体的工作是横向的；工作室是纵向的一条。工作室里开始的事照样出现在「正在做」（歌词条、便签），只是
  带着它是哪个工作室的。

## 一个工作室由什么组成：声明 + 通用部件

一个工作室主要是一份**声明**（`studio`，放在它的包里，像工作流一样）：

```js
studio: {
  id: 'plume', name: { zh: 'Plume 工作室', en: 'Plume Studio' }, icon: 'Feather',
  // 它管的几类东西（通用的存储）：每类一个表，字段有类型，能当表单、能当列表的列
  collections: {
    ideas:    { title: { zh: '选题' }, fields: [{ name: 'title', type: 'text' }, { name: 'notes', type: 'textarea' }, { name: 'account', type: 'ref:accounts' }] },
    accounts: { title: { zh: '账号' }, fields: [{ name: 'name' }, { name: 'positioning', type: 'textarea' }, { name: 'guide', type: 'textarea' }, { name: 'accent', type: 'color' }, …] },
    posts:    { title: { zh: '成品' }, from: 'runs', workflow: 'plume.post', fields: [{ name: 'platforms', type: 'status' }, { name: 'links', type: 'links' }] },
  },
  // 素材库：哪些文件算素材（它的运行文件夹里的、人传上来的）
  materials: { from: ['runs:plume.post', 'uploads'], kinds: ['image', 'markdown', 'pdf'] },
  // 开始一件事：哪个工作流，表单从哪来
  start: [{ id: 'write', label: { zh: '写一条' }, workflow: 'plume.post', from: 'ideas', fields: { title: 'title', text: 'notes', account: 'account' } }],
  // 首页：几块，每块一个通用视图
  home: ['start', 'working', { view: 'board', collection: 'ideas' }, { view: 'list', collection: 'posts' }, { view: 'library' }, { view: 'calendar' }, { view: 'form', collection: 'accounts' }],
  // 它自己的界面（可选）：比如 Plume 的手机预览
  views: { 'post-preview': … },
}
```

**通用部件**（做一次，每个工作室复用）：

| 部件 | 做什么 |
|---|---|
| 存储 | 每个工作室在盒子里一个地方（`~/.ruyix/studios/<id>/`）：每类记录一个表，带版本；引用别处的东西只存引用 |
| 首页 | 按声明排几块：开始（几个按钮）、在做（它的那几条「正在做」）、看板 / 列表 / 日历 / 素材库 / 表单 |
| 视图 | 列表、看板（按状态）、日历（排期）、素材库（缩略图格子，点开用查看器）、表单（按字段生成）、历史（它的运行，按天、按状态） |
| 开始 | 从一条记录开始工作流，表单按 `fields` 填好；开始后把运行和这条记录连上 |
| 排期 | 一件事「到点开始」或「到点发布」：用已有的定时任务（`docs/design/tasks.md`） |
| 出现在各处 | 导航一项、地图上一个地方、「正在做」和便签上标着是哪个工作室的、打开的东西按工作室归组 |
| 主智能体的工具 | `studio_list`、`studio_items`（看某类记录）、`studio_put`（加 / 改一条）、`studio_start`（从一条开始工作流）、`studio_schedule` |
| 技能 `ruyix-studio` | 主智能体怎么**用**工作室（「从选题里挑一个开写」「把这条排到明天早上」），和怎么**建**一个工作室：按一句话的描述写一份声明（只用已有的工作流和智能体，缺的工作流先用写工作流的技能写），检查通过再加进来 |

## Plume 工作室（样板）

- **首页**：最上面「写一条」（选账号、写想法、可选「先调研」、挑素材）；下面「在做」（它的几条，带进度，等你时琥珀色）；
  「选题」看板（想到 / 在写 / 已发）；「成品」列表（每条：标题、哪几个平台发了、链接、什么时候、哪个账号）；「素材库」；「排期」日历；
  「账号」。
- **账号**：每个账号一套：名字、定位、风格指南、语言、品牌色、署名、用哪些平台的连接、平台限制；写稿时选一个，写进智能体的任务说明
  （现在 `style` / `brand` / `limits` 做的事）。原来设置里的那一份搬过来当第一个账号。
- **选题**：一句话加备注；「开写」就是带着它开始一次运行；发完它变「已发」，挂上成品。
- **成品**：从运行的报告里读出发到哪、链接；没发完的标在哪一步。
- **素材库**：所有运行里的图片、卡片、原稿、调研，加上传上来的；写一条时可以挑。
- **排期**：一条成品排到某个时间发——到点出发布卡片（发出去仍要人批准）。
- **小红书**：发布卡片批准后，在共用的智能体浏览器里填好标题、正文、图片、话题，停在「发布」交给他（`browser_handoff`）；他在浏览器里
  登录一次就一直在。原来的扫码连接留着当后备，过一阵再拿掉。

## 做成了什么样（2026-10-18）

- **插件** `@ruyix/studio`（`core/plugins/studio`）：声明和检查 `lib/declare.js`，存储 `lib/store.js`（每个工作室一个 SQLite，
  带版本、删了能找回，素材在旁边），服务 `ruyixStudio` 和页面接口 `index.js`，主智能体的工具 `lib/tools.js`；页面（首页和
  几种视图、导航、地图上的地方）在 `src/`（workspace-15）。
- **运行和记录**：只记在运行上，`run.studio = { id, collection, record }`；一条记录做过哪些运行用工作台的 `runsOf` 查；运行结束时
  工作台调 `ruyixStudio.onRunEnd(run)`，记录的状态按声明里 `start.status` 走（Plume：开始「在写」，发出去「已发」，没做成退回「想到」）。
- **账号**：开始时复制一份进这次运行（`run.account`），叠在包的设置上只给这次运行用；没有工作室或没选账号时用原来的设置。原来的
  Plume 设定只搬一次成第一个账号。
- **配图**：选题里挑的素材开始时作为运行的附件交过去，运行留自己的一份。
- **排期**：声明里的 `remind`——记录的时间到了、还没做完，就在桌面「正在做」里挂一条「等你」（还没开写 / 还在写 / 写好了去发布），
  点开到那条记录，擦掉就不再提这个时间。到点发布本身仍要人批准。
- **主智能体**：`studio_list`、`studio_items`、`studio_put`、`studio_remove`、`studio_start`（人明说才开）、`studio_create`（按描述建一个
  人自己的工作室，存成 `studio.json`）；用法写在 `ruyix-system` 技能的「Studios」一节。在盒子里用真模型试过：记选题、撤回；建
  「读书笔记」工作室，通用的首页、看板、历史直接用上。
- **还在做**：小红书改用共用的智能体浏览器（workspace-ce）；主智能体知道现在几点、人在哪个时区（workspace-ce）。
