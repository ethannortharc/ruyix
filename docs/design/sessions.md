# 常驻会话、任务标记、自动整理：主智能体接管智能体的会话（设计）

2026-10-17 · Ethan：

- 打开的网页、文件、会话一多就很难整理，放哪儿都不好找。系统应该自动整理：放到合理的地方，整齐好看，收起来，要用的时候
  很容易找到、打开。
- 主智能体应该把整个系统当成操作对象，能操作里面任何东西，要有对应的技能和办法来整理这些东西。
- Claude Code、Codex 这些智能体，必要的时候起会话来跑。任务在跑的时候，桌面上要有一个在变化、有动画的东西（比如一棵树慢慢长，
  做完了开花或者结果）；做完看过之后放到固定的地方。所有智能体的任务都这样。
- 不要每次都起一个命令行：要有常驻的会话，由主智能体决定用常驻的会话还是再起一个新的。比如做一个复杂的项目，它能起两三个
  会话分别做，再做复查。这就要求能管理会话、往会话里输入、读会话的信息。
- 常驻会话和工作流要能共存：工作流是做事的固定方式（流水线），长会话是让智能体自己决定怎么做（对话）。至少共存；有必要、
  有可能的地方融合——有时候通过对话干活能省 token，整件事也更合理。

他定的（2026-10-17）：

- **四件一起做**。
- **任务标记**：不一定是植物（植物只是打比方：有生长、有完成）。要**通用**，在所有桌面、所有主题上都贴切，能看出有人在跑、
  做完了、出问题了，最好能看出做到哪一步；也可以跟着主题走——怎么做由我们考虑。效果要好。
- **整理怎么分组**：**先按事情分**（一个任务、一次运行、一个会话、一个项目的东西放一组）；找不到对应的事情，**再按类型分**。
  由主智能体看着分——人自己手动打开的东西也要能归进去。
- **主智能体开会话**：自己开，**同时最多 3 个**常驻的，再多先问人（卡片）。
- **会话和工作流**：共存；有必要、有可能时融合（见第 2 节）。

## 现在是什么样（盘点，2026-10-17，main f5e2c44）

- **智能体池（agent-hub）每一轮都起一次命令行**：Claude Code `claude -p --output-format stream-json`、Codex `codex exec --json`、
  pi `pi -p --mode json`（`runtimes.js` cliCommand / runCli），做完进程就退出。接着做 = 带着 CLI 的会话 id 再起一次
  （`--resume` / `resume <id>` / `--session`）。dsh 的智能体本来就是 dsh 里常驻的会话。
- **工作流的一次运行 = 池子里一个后台 job，每一步 = 一个任务**（一次新的命令行）。被打断的步骤接着做时带上 CLI 会话 id 和一段
  交接说明（engine.js resumeHandoff）。人按意见改（review 的 amend）在同一步里重跑。
- **三个 CLI 都有常驻的方式**（这台 Mac 上的版本都查过）：Claude Code 2.1.302 `--input-format stream-json`（进程不退，stdin 一行一条
  消息，每条一轮）；Codex 0.162.1 `codex app-server`（JSON-RPC，标着 experimental，一个进程能开几个对话；还有共用的 daemon 和
  `codex agents` 浏览会话）；pi 1.0.0 `--mode rpc`。
- **桌面上的「谁在干活」**：`window.__ruyixActivity`（workbench `src/activity.js`）有 runs（每次运行的步骤段 segs、当前步 cur、
  等人）、agents（每个在干活的步骤一个，带脉冲）、links、upcoming、finished。经典桌面的灯和跑道、星图的步骤环、古地图的驿站
  都画它。池子自己的 job、会话不在里面。
- **窗口**：`window.__ruyixDesk` open/close/focus，一个 id 一个窗口，位置记在浏览器 localStorage，能最小化；没有分组，换个浏览器就丢。
- **主智能体的系统工具**：desk_*、voice_*、apps_*（shell `systemTools`）；工作流和任务的工具在 workbench 的对话里
  （workbench_start_run、workbench_task_schedule…）。能撤销的直接做、记进工作记录；撤销不了的出卡片。

## 设计

### 1. 常驻会话（agent-hub）

**会话**是池子里的一个新东西：一个智能体 + 一个文件夹 + 一段对话 + （在用时）一个常驻进程。

- 记录 `session`：`{ id, agent, runtime, cwd, title, by: main | person | run | task, of?: { run, step } | { task } | { job },
  state: starting | idle | working | waiting | failed | closed, process: on | off, cli: <CLI 自己的会话 id>, turns, usage,
  createdAt, lastAt }`。对话的每一轮、每次工具调用记进会话自己的记录（和现在任务的 log 一样，按行追加）。
- **进程**：Claude Code 用 `-p --input-format stream-json --output-format stream-json --verbose`（加上现在的模型、effort、权限、
  MCP 参数）；pi 用 `--mode rpc`（`prompt` 一条消息，`agent_settled` 一轮结束，`get_state` 拿会话 id，`abort` 停下这一轮、进程留着）；
  Codex 用 `app-server`（一个会话一个进程，简单、互不影响；thread/start、turn/start、turn/interrupt）——还没做，先每轮一次 exec + resume。
  dsh 的智能体本来就常驻，会话不接它（它的对话就是 dsh 的对话）。（已做：Claude Code、pi，2026-10-17）
- **空闲关进程**：一个会话 20 分钟没有新消息，进程退出（`process: off`），会话还在；下次发消息再起，带 CLI 会话 id 接上
  （就是现在的 resume）。盒子重启后同样。
- **上限**：主智能体自己开的常驻会话（进程开着的）同时最多 3 个；要开第 4 个时出卡片问人。人自己开的不受这个限制。
  空闲的先让位：先关最久没用的进程。
- **操作**：开（智能体、文件夹、标题、第一句话）、发消息（在做时：排队，或打断后插话——和 dsh 的 queue/steer 一样）、读
  （从某处往后的对话和工具调用）、停（打断这一轮）、关（结束进程，会话留着能接着用）、删。
- **页面**：智能体页加一页「会话」：每个会话一行（智能体、文件夹、在做什么、任务标记、用量），点开是实时的对话：消息、工具调用、
  改了哪些文件，底下一个输入框，旁边停 / 关。
- **主智能体怎么选**（写进技能，第 6 节）：同一件事的后续、同一个文件夹 → 交给已有的会话（上下文还在，省 token）；不相干的、
  要并行的 → 开新的；上下文已经很大 → 开新的，带上摘要。复杂的项目：2–3 个会话，各在自己的 git worktree 里做一块，再开一个做复查
  （新眼睛：不复用写代码的那个），之间用智能体消息（core/messages）互相说。
- Codex 的 app-server 标着 experimental：起不来或协议对不上时，退回现在的「每轮一次 exec + resume」，会话照样能用，只是慢一点。

### 2. 会话和工作流：共存，能融合的地方融合

工作流 = **怎么做是定好的**：几步、谁做、哪里要人看、每步要交什么、证据记账。会话 = **怎么做由智能体自己定**：一段对话。
两者用的是同一批智能体、同一种进程；融合的地方是「一步在哪个会话里跑」和「对话里什么时候走流程」：

- **a. 一次运行的步骤接在一个会话里**：同一个智能体在同一次运行里的几步，默认接在同一个会话里——上一步读过的文件、定下的事
  还在，不用每步重新读简报，CLI 的提示缓存也接得上（省 token）。要「新眼睛」的步骤（复查、核对、评分）默认另开会话；工作流
  可以在步骤上写 `session: 'fresh'`（另开）或 `'run'`（接上）。引擎只在这些都成立时接上（workspace-ce）：
  - 运行时、模型、effort、权限、文件夹都和会话的进程一样（Claude Code 的权限和 MCP 在进程启动时就定了）；
  - 会话空闲——同一个智能体的并行步骤各开各的；
  - 上下文没超过上限；超过了 → 新会话，带一段交接摘要。
  - **退回重做 / 回到前面的版本**：不接已经做过后面步骤的会话（它的上下文里有要扔掉的东西）→ 新会话 + 这一步的简报。
  - 每一步的简报照样带上它的输入（接着做时短一些：「下一步：<步骤>，输入同前 + 变了什么」）；每一步照样要交 stage_result。
    **「对话里早说过了」不算做完。**
  每步交什么、证据怎么记都不变：账本还是记录，对话只是干活的地方。
- **b. 按意见改回到原来的会话**：review 步骤的「按意见改」交回写它的那个会话（同一步里）——它记得自己为什么这么写，改得更准，也省。
- **c. 对话里走流程**：在会话里（或对主智能体）说「按『公众号文章』那个流程做」→ 启动一次运行；运行里由这个智能体做的步骤可以
  就在发起它的会话里跑（`session: 'caller'`），条件同 a；做完的结果回到对话里。一次运行有它自己的 MCP（智能体留言，
  runs/<id>/messages.db），所以接用别的会话时引擎要让它的进程带上这次运行的 MCP 重新起（resume 本来就会重起）。这些步骤在跑时
  这个会话是忙的，运行页上写明。
- **d. 流程里交给会话自己做的一步**：工作流里可以有一步只写目标和**完成条件**，怎么做由会话自己定（用它自己的工具、可以多轮）。
  完成条件是**看得见、能核对的清单**（像准词的检查清单），由另开的核对步骤或脚本核对，不让会话自己给自己打分——否则它就只是
  一个带说明的智能体步骤，现在已经有了。
- **e. 定时任务可以有自己的会话**：任务上写 `session: 'task'` → 每次运行接着上一次的对话（记得昨天写过什么）。默认不开：
  定时的事通常每次独立。开了的：到点时它的会话正忙（人在里面聊）→ 这次运行排队等它空，或者另开一个，不穿插进去；
  上下文超过上限 → 新会话带摘要，同 a。
- **f. 对话 → 流程**：用会话摸索出一种做法后，可以说「把刚才的做法存成流程」→ 主智能体用写工作流的技能、拿 session_read
  读到的这段对话做输入写一个工作流，下次就按流程做。
- 运行页上每一步写明「在会话 X 里」；会话页上写明它给哪次运行的哪几步干过活。

### 3. 任务标记：一种在所有桌面上都贴切的「在干活」

不用植物：植物在星图、未来城市、水墨山水里都不搭。用**一个光点 + 一圈分段的环**——光在任何画面里都成立（星、灯、灯笼、墨圈、
霓虹），环天然能表示「做到第几步」。意思处处一样，样子跟着桌面走。

- **意思（所有桌面一样）**：
  - **排队**：暗的小点，环是虚的。
  - **在做**：点亮着、呼吸；环按步骤分段，做完的段亮起来，当前那段有光沿着走；每次工具调用、命令、模型调用闪一下
    （现在的 pulse）。做得越多，标记稍微变大一点——「长」，最多到 1.3 倍（再大地图上相邻的环会撞上）。
  - **等你**：琥珀色，慢而明显的一明一暗（和收件箱、桌面上「等你」用同一个琥珀色）。
  - **出问题**：出问题的那一段变红、断开，光点不规则地闪。
  - **做完**：环合上，亮一下（一圈光散开），然后收成一个稳定的小标记，挪到「做完的」那里（第 4 节）；有结果文件的带一个小角标。
  - **停了**：灰。
- **样子（跟着桌面和主题）**：默认的画法只用主题的颜色（强调色、琥珀、危险色；深色上发光，浅色上是描边和墨色），所以任何主题、
  任何壁纸不用另做就能用。地图和壁纸可以给自己的材质：星图 = 一颗星和它的星座环（现在就是这样）；古地图 = 岛上一盏灯 / 一座
  烽火，环是驿路的几站；水墨 = 一笔一笔画出来的墨圈（圆相）；未来 = 全息环。**等你**和**出问题**在所有材质里都用同样的琥珀和红。
- **数据**：一份 `work` 列表——工作流的运行、池子的任务、会话。**各自发布自己那一份，谁也不读谁的数据**（workspace-ce）：
  `window.__ruyixWork = { set(source, items), get() }`（外壳建它），每次变了发 `ruyix:work` 事件。工作台（activity.js）发
  `runs`，智能体池发 `tasks` 和 `sessions`；`get()` 合起来按要紧程度排好。每一项是
  `{ id: 'run:<id>' | 'task:<id>' | 'session:<id>', kind: run | task | session, title,
  agents: [{ id, kind: claude | codex | dsh | system | person, state, step }], state: queued | working | waiting | failed | done | stopped,
  segs: [{ title, st: done | run | wait | fail | skip | todo }], cur, pulse, startedAt, endedAt, ok, seen, result? }`。
  - id 带类型，第 5 节组的 `of`、地图上的地方都用同一个 id 指它。
  - segs 带步骤标题：地图悬停时显示「等你：<步骤>」「<步骤> · 12 分钟」。
  - agents：一个会话一个，一次运行可以有几个；地图按 kind 给环上的星 / 无人机上色。
  - **排序**：`work` 按要紧程度排好——等你、在做、出问题、做完没看、其余；每个桌面都取前 N 个（地图着色器最多 8 个），取法一样。
  - 各桌面只读 `__ruyixWork.get()` 画标记；`__ruyixActivity` 原来的 runs / agents 保留到地图都换过来。
- **一个画法给所有桌面用**：shell 出一个 `<WorkMark>`（SVG/Canvas，经典桌面、小组件、窗口标题栏都用）和一份给着色器桌面的
  uniform 打包（星图、古地图已有 uTask 那一套），材质由主题 / 地图的定义给（`mark: { ... }`）。

### 4. 做完的：固定的地方

- 做完的标记不消失，挪到**做完的**：经典桌面是 dock 旁边一个小托盘；地图上就用已有的「记录」那个地方——古地图是爱尔兰，
  星图是狮子座，未来是档案平台。悬停显示没看过的数量；有没看过的，那个地方微微发光。
- **看过没有**（`seen`）记在盒子里（不是浏览器），换浏览器也一样；有一个操作标记「看过了」。归结果和记录的那边（workspace-ce）存。
- 点一个 → 打开它的结果（结果查看器：Markdown、图片、PDF、网页、改了的文件）。看过以后收进**记录**（运行和会话的历史，
  按天、按事情找）；桌面上只留最近没看的。

### 5. 打开的东西：先按事情分，再按类型分

- **登记**：每个打开的东西（网页窗口、插件窗口、文件、终端、浏览器、会话、Linux 应用）登记一条：`{ id, kind, title, icon,
  reopen（怎么再打开它）, of?（属于哪件事：run / task / session / job / 文件夹）, openedAt, usedAt }`。从运行、任务、会话里打开的
  天然知道 `of`。记在盒子里（`~/.ruyix/open.json`），刷新、换浏览器都还在。
- **分组**：有 `of` 的归到那件事的组（组名就是那件事的标题）；人手动打开、没有 `of` 的，由主模型看标题、地址、内容猜它属于
  哪件事（一个小活，很便宜）；猜不出来的按类型分：网页、文件、终端、应用。人把一样东西拖到别的组 → 记住（同一个网站、同一个
  文件夹以后也这样归）。
- **桌面上**：每组是一张收起来的卡片（名字、里面几样东西的图标、那件事在跑的话带任务标记）；点开，这组的窗口在桌面上整齐排开
  （按数量平铺），其它组的收起来；一阵子不用自动收回去。⌘K 能搜到任何一样东西，选中就打开它所在的组。
- 地图桌面上：一组 = 一个地方（岛上的一片房子、星图的一颗星），点开同样在面板里排开。

- **做成的样子（2026-10-17，已做）**：`@ruyix/shell/open` 的 `openRegistry()`（`window.__ruyixOpen`）：`add({ id, kind, title, hint?, of?,
  win?, reopen: { event, detail } })`、`use`、`fold`、`foldGroup`、`pin`、`close`、`reopen`、`move(id, group)`、`open(id)`（发它的 reopen
  事件）、`list`、`groups()`、`closed()`，变了发 `ruyix:open-things`。分组的规则在 `open-model.js`（页面和盒子共用）：人放的 → 所属的事
  （of）→ 学到的规则（同一个网站、文件夹、应用）→ 类型；类型组不带标题，由桌面按人的语言写。盒子里记在 `~/.ruyix/open.json`，
  页面把改动当成操作发过去（`/api/ruyix/open`），最多 200 个打开的 + 50 个最近关掉的。已经接上的：主窗口显示的页面、桌面上的窗口
  （打开时给了 reopen 的：应用中心的应用和终端）、会话页上的会话；工作台的运行页、结果文件、浏览器由 workspace-ce 接；卡片由
  workspace-15 画。主智能体的工具：`open_list`、`open_focus`、`open_group`、`open_fold`、`open_close`（撤销：`open_reopen`）。
- **名字跟着页面的语言（2026-10-22）**：打开的人知道两种说法时一起给（`names: { zh, en }`；应用中心的应用、终端都给），桌面、
  程序坞、抽屉、窗口标题按页面当前的语言显示，换语言不用重开；只有一种说法的（网页标题、文件夹）照原样。之前存下的只有一个名字，
  应用中心用 `rename(id, { names })` 补上（只改名字，不动顺序、不展开）。起因：英文页面打开过的终端、智能体浏览器，换成中文后左侧
  还是英文。

### 6. 主智能体管整个系统

- 新工具（shell systemTools，规矩照旧：能撤销的直接做并记撤销；撤销不了或对外的出卡片）：
  - 打开的东西：`open_list`、`open_focus`、`open_group`（归组 / 改组）、`open_tidy`（整理：收起不用的、排开要用的）、`open_close`。
  - 会话：`session_list`、`session_start`、`session_send`、`session_read`、`session_stop`、`session_close`。
  - 工作流和任务：把 workbench 已有的启动 / 停止 / 定时 / 立即运行也给主智能体（现在只在对话页的助手里）。
  - 文件：在 home 里列、读、移动、改名（删除 = 挪到回收站，能撤销）。
- **技能「Ruyix 系统」**：系统里有什么（桌面、窗口和组、会话、工作流和任务、应用、设置、文件）、在哪、用哪个工具、哪些要先问人、
  会话和工作流怎么选（第 1、2 节的规矩）。主智能体每次都带着它。

## 分工（建议，三个会话一起做）
