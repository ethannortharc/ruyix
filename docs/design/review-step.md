# 审阅步骤（设计）

2026-10-17 · Ethan：工作流做到中间某一步要等人审，这一步产出的文档（或视频，任何东西）要整个摊开在那儿，人在上面提意见
（主要是提意见，修改让 agent 做；人也可以自己改），agent 知道人改了什么、说了什么，按意见改完再给人看。这一步里面是一个
小循环：agent 收集之前做的东西交给这个界面，人看完提交，agent 再做。要相对独立，工作流里任何位置、任何阶段都能加，
视频、内容、所有工作流都能用。

**状态（2026-10-17）：已做完。** 代码在 `core/workbench/lib/review.js`（这一步、意见、给 agent 的任务、检查它的回复）、
`src/review.jsx`（卡片上的一行和大窗口的审阅页）；`lib/person.js` 把所有 `ask: 'review'` 交给它；工作流编辑器里
「人审阅」多了四项设置。检查在 `check.mjs`「a review with a loop of its own」。和下面不一样的地方记在最后。

## 现在有什么

- 「人审阅」这一步（`lib/person.js` 的 `personStep`，`ask: 'review'`）：收件箱里一张卡片，通过、退回到某一步（带一段意见）、
  停止；卡片上可以挂领域包的编辑器（`editor: '<包>.<名字>'`，Plume 的各平台稿子就是这样）。
- 运行的版本（`lib/versions.js`）：每一步一个版本；人改文件（`editFile`）是一个新版本，运行等人时也能改。

缺的：内容不在审阅的地方摊开（要去「文件与版本」里找）；意见只能写一整段，没法指着某一句；要改只能退回前面那一步整步
重跑；没有「agent 当场按意见改、再给你看」的循环。

## 这一步做什么

升级现有的「人审阅」，不另起一套：所有 `ask: 'review'` 的步骤都变成这样，没写新设置的照旧能用。

1. **收集**：这一步要给人看什么——`show`（运行文件夹里的路径，可以用 `*`）；不写就是上一步改了的文件。打开 `gather`
   时，先让 agent 写一份审阅说明（`review/<步骤>/note.md`：做了什么、要人重点看哪几处），放在最前面。
2. **呈现**：按文件类型选显示方式：
   - Markdown：排好版显示；选中一段写意见（意见挂在那段文字上）；能切到编辑。
   - 文本、代码：带行号；选中几行写意见；能编辑。
   - JSON：按字段显示；意见挂在字段上。
   - 图片：在图上框一块写意见。
   - 视频：播放到哪写意见就挂在哪个时间点（带那一帧的缩略图）。
   - 网页（HTML）：沙盒里预览；意见写整体的。
   - 领域包自己的显示方式（`display: '<包>.<名字>'`，就是现在的 `editor`；Plume 的各平台预览是第一个）。
   意见也可以写整体的，不挂在任何地方。
3. **人改**：直接改的内容存成一个新版本（「人改的」）；agent 拿到的是这次审阅开始以来人改动的差别。
4. **提交**：卡片上几个选择——
   - **按意见改**（有意见或改动时）：这一步的 agent 当场改，改完是新的一轮，人再看；
   - **通过**：接着跑后面的步骤；
   - **退回到 X**（写了 `back` 时）：照旧，意见带给那一步；
   - **停止**。
5. **agent 改**：默认是做出这份内容的那个 agent（前面最近的 agent 步骤的智能体），`revisedBy` 可以指定。它拿到：每条意见和它挂的位置
   （文件、引用的原文和前后几个字、行号、时间点、框的位置）、人改动的差别、这一步的说明。它改文件，不撤销人的改动，
   **每条意见回一句**：改了，或者没改、为什么。检查不过（有意见没回、文件不在）就在同一个任务里让它补。
6. **一轮一个版本**：每一轮开始时的样子都有版本；界面上能把这一轮和上一轮对比着看，意见旁边是 agent 的回复，
   人可以把没改好的意见重新打开。
7. `rounds`：最多改几轮（默认 5），到了只剩通过、退回、停止。

## 设置（工作流编辑器里「人审阅」的设置）

```js
{ use: 'person', ask: 'review', title: '看原稿', text: '…',
  show: ['draft.md'],        // 给人看什么（不写：上一步改了的文件）
  gather: false,             // 先让 agent 写审阅说明
  revisedBy: 'draft',        // 哪一步的 agent 按意见改（不写：前面最近的 agent 步骤；false：不让 agent 改）
  back: 'draft',             // 可以退回到哪一步
  rounds: 5,                 // 最多改几轮
  display: 'plume.posts' }   // 领域包的显示方式（不写：按文件类型）
```

领域包写代码时用同一个函数：`reviewStep(w, { … })`（从 `@ruyix/workbench/person` 引入，和 `personStep` 一样）。

## 数据

- 意见存在运行上：`run.reviews[<步骤>] = { round, rounds: [{ n, version, comments, edits, submittedAt, agent }] }`。
  一条意见：`{ id, file, at, text, status: open | done | declined, reply }`，`at` 是挂的位置
  （`{ quote, prefix, suffix }`、`{ lines: [a, b] }`、`{ field }`、`{ box: [x, y, w, h] }`、`{ time }`，或者没有）。
- 写到一半的意见边写边存（刷新、关掉不会丢），提交时才交给 agent。
- 每一轮的意见、选择和 agent 的回复记进记录（这是人和 agent 之间的事，要留证据；和「留言」不同）。

## 界面

- 收件箱里的卡片写「看原稿 · 第 2 轮 · 3 条意见」，按钮「打开审阅」。
- 审阅页（大窗口）：左边文件列表（审阅说明在最前），中间是内容和挂在边上的意见，右边是所有意见、agent 的回复、
  这一轮和上一轮的对比，底下是几个选择。
- 运行页面「过程」里，等人审阅的那一步也有「打开审阅」。

## 做的时候改了的

- 「谁按意见改」的设置叫 `revisedBy`（填一个 agent 步骤的 id，`false` 是不让 agent 改），不叫 `agent`：agent 步骤里
  `agent` 是智能体池里的智能体，同一个名字两个意思容易弄混。
- 「按意见改」这个选项的动作叫 `amend`（核心代码里不许出现 rework 这个词：那是一个领域的说法）。原来的「要改」
  （退回某一步）在中文里改叫「退回重做」，免得和「按意见改」分不清。
- 卡片上打字写的那一段，算一条对整体的意见。
- 退回到前面的步骤以后再回到这一步，是新的一次审阅；之前的每一轮和意见留在 `past` 里。
- 「按意见改」时既没有待改的意见、也没有人自己的改动：不派任务，记一笔，再问一次。
- 意见里的文字位置用浏览器的 CSS Custom Highlight 标出来，不改动页面的 DOM（Markdown 是 React 画的）；不支持的浏览器
  只是不高亮，意见照样能写、能看。
- 视频、音频、图片、PDF 从运行文件夹按流读（`GET /api/ruyix-workbench/work`，能拖进度）；只给这几类，网页和别的文件
  不从这里给（浏览器会运行它们）；只在文件夹里面，不经过链接。
- Plume：「看原稿」由写稿的智能体按意见改（`show: ['draft.md']`, `revisedBy: 'draft'`）；「看各平台的稿子」不当场改
  （`revisedBy: false`），因为卡片图是前一步按稿子做的，当场改了稿子图不会跟着变——要改就退回「各平台的稿子」。
