# Plume · 多平台发布

## 平台资料与适配审核

同一份原稿按小红书、X、公众号分别重写开头、结构、篇幅、调性、标签和视觉文案，保留事实、数字、限定条件和账号风格。`plume.post` 在生成卡片后增加独立的只读平台适配审核：覆盖每段发布文字（包括标题、摘要、标签、封面和卡片），检查事实与原稿的一致性、调性、开头、结构、格式、图文一致性和读者价值。它不是对原稿来源的再次独立事实核查，也不承诺曝光效果。

- Plume Studio 的「平台资料」支持搜索、平台筛选、来源与可访问性、更新期限、历史版本，以及「立即调研」「每周更新」和暂停/恢复。周期更新使用现有 Workbench 调度器；需要 Ruyix 服务运行并配置可联网的智能体。
- `plume.platform-research` 检索并读取来源、保留有界证据，再由独立只读智能体核对每条观察、摘要、冲突项及来源身份和证据。只有通过的版本进入资料库；失败保留已有版本。官方事实、第三方观察和编辑建议分开，不把传言或评分升级成平台规则。研究不会修改账号、硬限制、费用配置或发布权限。
- 写作在首次平台改写时固定资料快照；后续资料更新只用于新运行。过期资料不进入自动改写建议，界面仍显示其版本和过期状态。旧审核契约下的资料同样保留版本，但不用于自动建议；资料正文不会经审核输入的另一条路径重新进入提示。当前默认数值限制由代码和用户实测设置控制，不能视为所有账号的官方保证。
- 手改平台稿、原稿、相关配图或编辑设定后，旧审核不再适用。保存后点「重新检查适配」，`plume.adaptation-review` 对当前版本只读检查；过程中再次变化会丢弃审核结果。审核状态保存在服务端，编辑审核 JSON 文件不能放行。审核通过后仍需人工审阅和每个平台的发布确认。
- 每轮自动适配失败最多回改两轮，然后停下展示问题；一次通过后，用户要求的新一轮修改获得新的修复预算。审核提交不满足逐字覆盖、证据摘录或长度契约时，会把错误直接返回审核者纠正。已发布或交接给浏览器的版本保持冻结；其他未发布平台仍可编辑和单独重审。已有评分只学习明确的作者偏好，账号指南优先于学习偏好和平台编辑建议。

来源、可复用开源流程及未核验项见 [平台调研](../../docs/research/plume-platform-intelligence.md)。平台资料的研究记录与正文主题调研互相独立。


一篇内容发到小红书、X 和公众号，做成 Ruyix 工作台的一个工作流（`plume.post`）。来自独立的 Plume 项目
（`workspace/plume`）：它的平台规则、提示词、卡片模板、小红书的半自动发布和 X 的接口发布都搬了过来，跑在工作台上，
所以每一步都有记录、有版本、能回退，要发出去的东西都先变成卡片等你批准。

## 一次运行

| 步骤 | 谁做 | 做什么 |
|---|---|---|
| 收下请求 | 系统 | 标题、要写什么、本篇受众、账号、平台、参考链接、参考资料和发布配图 |
| 调研 | 智能体（可联网） | 只在表单勾了「先联网调研」时做：`research.md`，每条结论标来源 |
| 写原稿 | 智能体 | 先写 `outline.md`（读者问题、结构、证据），再写 `draft.md`：不针对平台的完整原稿；要你补充真实经历的地方标【待补充：…】 |
| 看原稿 | 你 | 通过，或者写下要改的地方退回重写；也可以在「文件与版本」里直接改 `draft.md`（改了就是一个新版本） |
| 改写成各平台的稿子 | 智能体 | `posts/xhs.json`、`posts/x.json`、`posts/wechat_mp.json`：按各平台的规则和读者重写。交稿时逐个检查，不合规的地方当场告诉它，它在同一个任务里改好再交 |
| 做卡片和封面 | 系统 | 小红书的封面和内页卡片（3:4）、X 的横版封面（设置里打开时才用）、公众号封面（2.35:1）在 `cards/`；公众号文章排好版的 HTML 在 `posts/wechat_mp.html` |
| 平台适配审核 | 只读审核智能体 | 检查完整发布文字与原稿的一致性、调性和平台格式；不通过时按意见回改 |
| 看各平台的稿子 | 你 | 一张卡片里每个平台一个标签：手机样式的预览、检查结果、能直接改的字段。存下来就是一个新版本，卡片会重做 |
| 发布卡片 | 系统 | 每个平台一张发布卡片；你批准了才会发出去 |
| 出报告 | 系统 | 记录、版本、发到了哪里 |

发布卡片批准前会按文件夹里**现在**的内容再检查一次，有要改的地方就不让批准。

## Plume Studio 的日常使用

1. 在「账号」保存口吻、读者定位、品牌和发布连接；运行开始时固定账号快照。旧设置仅配置过语言或连接时也能迁入账号。
2. 「写一条」先打开完整选题表单，确认本篇受众、平台、参考链接和资料。参考材料可选择素材库中的 Markdown、PDF 或参考图片；发布图片单独放在「配图」。**参考图片不会自动出现在帖子里。** 需要读取网页时打开「先调研」；关闭调研时，链接本身不被当作已验证事实。
3. 原稿审核同时能查看提纲、调研笔记和来源清单。平台稿审核会检查所有平台、记录你实际查看的版本；正文和渲染错误、有未保存内容时阻止通过，关闭窗口前提醒。配图大小、张数等问题仍展示，但只阻止对应平台的发布卡，不阻塞其他平台。
4. 流程完成是「待发布」，每个平台都确认发布后才是「已发」。未发布稿仍可重新打开平台稿审核卡编辑。写入前被拒绝的保存不会改变原有卡片证据；已写入后渲染失败时显示「请保存此版本并重做卡片」，可直接再次保存。正文或卡片被外部编辑后也需要重做。「再改」会返回写原稿，并重新经过两次审核。
5. 「基于此稿建立新选题」复制原稿和原始附件的独立素材快照，保留受众、平台、参考链接及仍存在的账号。新选题从「想到」开始，由你补充修改方向再启动；原选题、文件和发布记录不动。最多复用 19 个原始附件（另有一份原稿），每份不超过 25 MB。20 个附件的运行请新建选题后选择需要的资料。

只有「想到」状态能启动原选题。已经发布、交给小红书浏览器等待你发布的版本不能再由平台编辑器修改；重新创作用新选题。部分 X 串推保留恢复入口，已发布的开头或图片有变化时，恢复仍会拒绝。已确认发布的前缀仅作上下文，适配审核覆盖剩余内容；未知结果可先在卡片点「记录核对结果」，保存已发布帖子 ID 或确认未发布，此操作不会发帖。回执改变审核范围后，剩余内容需重新审核。

平台正文与生成卡片绑定内容摘要。渲染失败、渲染途中外部改动、过期的审核摘要均不能通过；保存和发布互斥；保存期间退回重写或停止也需等待，旧窗口保存会报告版本冲突。工作台的通用「从此步骤继续」同样不能重写已发或已交接的运行。「文件与版本」编辑会在写入前保护已发布平台的正文、HTML、卡片和所用配图（含目录别名路径）；版本回退在任何停止或文件恢复之前拒绝。其他未发布平台仍可编辑保存，参考文档不会因其他平台发布而变成只读。原始文件编辑与发布、保存、审核决定共用同一运行锁；生成中的运行不能同时批准旧发布卡。小红书的人工「我已经发布了」仅接受已完成发布卡上那一版，公众号仍需走自己的发布确认。旧版已发布历史不会被重写；旧版未发布稿首次打开可能需要保存以重建卡片摘要。

这不代替事实审核或平台端核验：调研笔记有来源格式校验，稿件事实仍由你审核；小红书交接后你在网站手工修改的实际内容，Ruyix 无法逐字验证。系统保留交接时的内容摘要。

已发布或已交接运行的继续、恢复、结果重启与任务「再改」，会在关闭浏览器、重置步骤或改变 Studio 状态之前拒绝。重新创作期间，包括暂停等待审核或人工帮助时，旧发布卡不能批准。

## 三个平台怎么发

- **X**：通过 X 接口（OAuth 2.0）。在「连接」页加一个 X 类型的连接（id 默认 `x`），填 X 开发者应用的 Client ID（有
  secret 就填上），点「连接 X」授权。图片挂在第一条，串推一条接一条回复；中途断了，再批准一次会从断的地方接着发，
  不会重复发。按量计费：普通帖约 $0.015/条，带链接的 $0.2/条（2026-10-22 官方 pay-per-use API 价目估算；卡片显示估算，实际以控制台为准）。
- **小红书**：在**智能体浏览器**里半自动（应用中心 → 智能体浏览器；你和所有智能体共用的那个）。你在它里面登录一次小红书
  创作服务平台，之后一直登着。批准发布卡片后，它排队拿到浏览器，开一个自己的标签页，上传图片、填好标题、正文和话题，
  然后把最后一下交给你：桌面亮琥珀色、卡片上有「打开智能体浏览器」，你检查后**自己点「发布」**。网站显示发布成功时
  运行会记下来，浏览器交回给别的智能体（标签页留着）。没登录时卡片会说清楚，登录后重试这张卡片。某一步自动填写失败时
  停在那里，剩下的你在同一个标签页里手动完成。
  没有智能体浏览器时（还没装）照旧：在「连接」页加一个「小红书创作服务平台」类型的连接（id 默认 `xhs`），「扫码登录」，
  批准后在卡片上看得见的浏览器里填好，等你点「发布」。
- **公众号**：复制粘贴。当前实现使用人工后台路径，不推定账号具备 API 发布权限。卡片上按后台的填写顺序列出步骤：打开后台、复制标题、复制摘要、
  复制排好版的正文（富文本和内联样式，仍需在平台后台预览检查）、下载封面。发表之后把文章链接贴回卡片再批准。
  稿件或文件更新后，已打开的卡片会重新读取；新内容清除旧版的步骤勾选，同版重读保留已复制步骤。复制遇到版本变化时会显示原因，并提供重新读取。

## 设置

在工作台设置里，`packs.plume`：

```json
{
  "accounts": { "x": "x", "xhs": "xhs" },
  "style": { "name": "", "positioning": "", "guide": "", "language": "简体中文" },
  "brand": { "accent": "#d4380d", "background": "#fffaf3", "signature": "" },
  "x": { "premium": false, "cover": false },
  "limits": {}
}
```

- `accounts`：各平台用哪个连接。
- `style`：账号名、定位、风格指南，会写进每个智能体的任务说明。
- `brand`：卡片的主色、底色、底部署名。
- `x.premium`：付费会员（单帖可以更长；接口是否支持待实测）。`x.cover`：X 的第一条带上生成的横版封面。
- `limits`：实测之后覆盖平台限制，例如 `{ "xhs": { "titleMax": 20, "imagesMax": 9 } }`。没实测过的限制在规则里标着「待实测」。

## 文件夹

一次运行的文件夹里：`research.md`、`draft.md`、`posts/<平台>.json`、`posts/wechat_mp.html`、`cards/*.png`、
`attachments/`（参考资料和发布配图，分别标记用途）。每一步之后都是一个版本，在运行页面的「文件与版本」里能看历史、比较、改。

## 代码

| 文件 | 内容 |
|---|---|
| `pack.js` | 工作流、发布动作、卡片用到的接口（`plume.posts`、`plume.savePost`、`plume.article`） |
| `lib/platforms.js` | 三个平台的限制（证实状态和来源）、写作要求、字段、检查；X 的加权字数 |
| `lib/article.js` | Markdown → 公众号能粘贴的 HTML（样式内联） |
| `lib/cards.js` | 卡片和封面的 HTML 模板（由工作台的无头浏览器渲染成 PNG） |
| `lib/xhs.js` | 小红书的连接类型（扫码登录、保存登录会话）和自动填写；页面选择器来自 xiaohongshu-mcp |
| `lib/x.js` | X 接口：分片上传图片、发帖和串推 |
| `src/` → `client.js` | 页面：各平台的预览和编辑（看各平台的稿子那张卡片）、发布卡片 |

`npm run check --workspace=@ruyix/plume`：平台规则、文章 HTML、卡片、图片尺寸；用假的智能体完整跑一次（原稿、审阅、改写时当场修正、你在卡片上的
修改、发布卡片；X 发到假的接口、公众号带链接批准、小红书登录失效时拒绝）；在真浏览器里对一个仿制的小红书发布页做一遍自动
填写（没有 Playwright 的机器跳过）。不连真实平台。

回归覆盖真实 Workbench + Studio 引擎的调研→原稿→审核→平台稿→发布卡→状态回写，包括参考资料映射、参考图片不外发、渲染故障与恢复、保存/发布双向互斥、保存时的重做/停止拒绝、多窗口陈旧保存拒绝、通用继续不重写已发布运行、真实文件编辑和版本回退的前置拒绝、目录别名绕过拒绝、原始编辑与发布双向互斥、其他未发布平台仍可保存、渲染中的外部编辑、过期审核拒绝、X 串推恢复、小红书确认版本校验、发布后编辑拒绝、复用快照不改原记录，以及隔离运行里的符号链接拒绝。`research-check.mjs` 另外验证来源去重/引用、提纲必需和旧账号迁移。

构建：`npm run build --workspace=@ruyix/plume`。测试里的智能体和平台 API 是本地夹具，浏览器仅访问本地仿制页面；没有用真实账号发帖。
